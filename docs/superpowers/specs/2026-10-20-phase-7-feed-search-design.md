# IOITube — Фаза 7: стрічка, теми, сортування, блоки Shorts (Design Spec)

**Date:** 2026-10-20
**Status:** На ревʼю власника
**Батьківська спека:** `docs/superpowers/specs/2026-10-14-youtube-clone-design.md`
**Попередні фази:** 1–6 реалізовано

Ця спека доповнює батьківську і **скасовує** такі її положення:

- «Головна — плаский список відео, без пагінації» → стрічка **нескінченна**, з блоками Shorts.
- «Пошук — сітка 2 стовпці» → пошук показує **один стовпець великих карток**.
- Фіксований набір категорій `FEED_CATEGORIES` (`музика`, `ігри`, `спорт`, `фільми`, `технології`) → **пули запитів на тему** з випадковим вибором.

---

## 1. Мета і скоуп

Запит власника після тестування на телефоні:

| № | Запит | Що робиться |
|---|---|---|
| 1 | «зробити таке меню зверху, яке буде переключати/сортувати відео» | Рядок чипів тем на «Головній» + окремий чип сортування |
| 2 | «на сторінці пошуку — видавати результати більшими, а не в 2 стовпці» | Пошук: один стовпець, 16:9 на всю ширину |
| 3 | «при оновленні на головній відео не оновлюються… зробити більш рандомним» | Кожне оновлення/довантаження — новий випадковий запит, дедуплікація показаного |
| 4 | «додати блоки шортс на головній, після кожного 4-го відео» | `ShortsBlock` у стрічці, 2 картки 9:16, тап → вкладка Shorts на цьому відео |
| 5 | «шортси більш рандомні, багато з одного каналу» | Максимум **1 шортс з каналу** на партію, випадкові канали й теми |

**Поза скоупом фази 7:**

- серверне сортування YouTube (див. §2 — недоступне в 0.26.5);
- пагінація результатів пошуку (пошук і далі показує одну сторінку видачі);
- збереження теми/сортування між запусками застосунку;
- персоналізація, історія переглядів, підписки;
- кешування шортсів у Room.

## 2. Дослідження (перевірено на реальній мережі 2026-10-20)

| Питання | Результат |
|---|---|
| `getSearchExtractor(query, filters, sortFilter)` | Третій аргумент **ігнорується** для YouTube: у байткоді `YoutubeSearchQueryHandlerFactory.getUrl` `sortFilter` не читається |
| URL з `&sp=CAI%3D` / `CAM%3D` (і подвійне кодування) | `SearchExtractor.NothingFoundException` — серверне сортування недоступне |
| Порядок видачі YouTube | Стабільний для того самого запиту: саме тому refresh показував ті самі відео |
| Дата публікації | `StreamInfoItem.getUploadDate()` → `DateWrapper` (реальна дата), `getTextualUploadDate()` → «4 дні тому» |
| Shorts | Поточна логіка бере ≤6 каналів і **весь** їхній таб Shorts → один канал може зайняти всю стрічку |

**Висновок:** сортування робимо клієнтськи; «рандом» — за рахунок пулу різних запитів, а не перемішування однієї видачі.

## 3. Архітектура

### 3.1 Домен

```kotlin
enum class FeedTopic(val id: String, val label: String) {
    ALL("all", "Усі"), MUSIC("music", "Музика"), GAMES("games", "Ігри"),
    SPORT("sport", "Спорт"), FILMS("films", "Фільми"), TECH("tech", "Технології"),
    NEWS("news", "Новини"), HUMOR("humor", "Гумор"), AUTO("auto", "Авто"),
    FOOD("food", "Кулінарія"), TRAVEL("travel", "Подорожі"),
}

enum class FeedSort { RELEVANCE, NEWEST, POPULAR }

sealed interface FeedItem {
    data class Video(val video: VideoSummary) : FeedItem
    data class ShortsBlock(val id: String, val shorts: List<VideoSummary>) : FeedItem
}

data class FeedPage(val videos: List<VideoSummary>, val exhausted: Boolean = false)
```

`VideoSummary` отримує `uploadedAt: Long? = null` (epoch millis з `DateWrapper`). Поле **не** зберігається в Room: кеш віддається лише для «Усі + Релевантність», де сортування не потрібне; `cached_videos` не змінюється, міграція БД не потрібна.

### 3.2 Репозиторії та use cases

```kotlin
interface FeedRepository {
    fun getFeedPage(topic: FeedTopic, sort: FeedSort): Flow<UiState<FeedPage>>
    fun getFeedShorts(count: Int, excludeIds: Set<String>): Flow<UiState<List<VideoSummary>>>
}
```

- `VideoRepository.getHomeFeed()` видаляється, його місце займає `FeedRepository`.
- `ShortsRepository` (вкладка Shorts) не змінюється.
- Нові use cases: `GetFeedPageUseCase`, `GetFeedShortsUseCase`.
- Кеш: `SOURCE_HOME` зберігає першу сторінку «Усі + Релевантність» (офлайн-режим). Для теми/сортування кеш не читається й не пишеться.

### 3.3 Джерело (NewPipe)

`NewPipeRemoteDataSource`:

- `fetchFeedPage(topic: FeedTopic): List<RawVideoSummary>` — випадковий запит із пулу теми; для `ALL` — 2 випадкові теми, по одному запиту, результати чергуються (`interleave`).
- Пул запитів (по 3–4 варіанти на тему), напр.: `GAMES → ["ігри", "огляд ігор", "ігрові новини", "проходження ігор"]`, `NEWS → ["новини", "новини України", "світові новини"]`, `FOOD → ["кулінарія", "рецепти", "готування"]`.
- `Random` інжектується (`@Provides fun provideRandom(): Random = Random.Default`), щоб тести були детерміновані (`Random(seed)`).
- `fetchHomeFeed()` більше не використовується; `FEED_CATEGORIES` видаляється.
- `fetchFeedShorts(count, excludeIds)`:
  1. бере випадковий запит із `SHORTS_QUERIES`;
  2. збирає канали з результатів, перемішує, бере до `SHORTS_CHANNEL_LIMIT = 10`;
  3. з таба Shorts кожного каналу бере **один** випадковий шортс (не в `excludeIds`);
  4. перемішує канали, повертає до `count`.
  Один канал → максимум один шортс у партії.
- `fetchShorts()` / `fetchMoreShorts()` для вкладки Shorts також переводяться на правило «1 шортс з каналу» (щоб не було концентрації), решта логіки без змін.

### 3.4 HomeViewModel

```kotlin
data class HomeUiState(
    val topic: FeedTopic = FeedTopic.ALL,
    val sort: FeedSort = FeedSort.RELEVANCE,
    val items: List<FeedItem> = emptyList(),
    val loading: Boolean = true,
    val loadingMore: Boolean = false,
    val error: String? = null,
    val loadMoreError: String? = null,
    val exhausted: Boolean = false,
    val fromCache: Boolean = false,
)
```

Поведінка:

- `selectTopic(topic)` / `selectSort(sort)` — скидають `items`, показані id, `exhausted`; вантажать першу сторінку.
- `refresh()` — те саме, але тема й сортування лишаються; кеш не показується (тільки свіжі дані).
- `loadMore()` — захист від паралельних викликів; якщо після фільтра дублікатів сторінка порожня, повторює запит до 3 разів (кожен — новий випадковий запит), далі `exhausted = true`.
- Розмір сторінки — 20 відео (одна сторінка пошукової видачі YouTube).
- Помилка довантаження → `loadMoreError`, стрічка лишається; кнопка «Повторити» викликає `loadMore()`.
- Блоки: після кожного 4-го **відео** в `items` додається `ShortsBlock` із 2 шортсами (окремі канали). Кількість шортсів на сторінку = `2 × кількість нових блоків`; запит робиться один раз на сторінку.
- Сортування застосовується до відео сторінки перед додаванням: `NEWEST` — `uploadedAt` спадно, `POPULAR` — `viewCount` спадно, `RELEVANCE` — порядок видачі.
- Дедуплікація за `id` відео — єдине місце, ViewModel.

## 4. UI

### 4.1 «Головна»

- Під системним топ-баром — `LazyRow` чипів: `Усі`, теми, і окремий чип `Сортування` (іконка + поточна назва) з `DropdownMenu` (`Релевантність`, `Нові`, `Популярні`).
- Вибір чипа теми одразу скидає й перезавантажує стрічку; індикатор завантаження — як зараз (`LoadingBox`).
- `LazyColumn` з `FeedItem`:
  - `Video` → наявний `VideoCard`;
  - `ShortsBlock` → заголовок «YouTube Shorts» з іконкою + рівно **2 картки** 9:16 у рядку (заголовок, канал, перегляди), без горизонтального скролу; «…» праворуч відкриває вкладку Shorts.
- Тап по шортсу → `navController.navigate(Routes.shorts(videoId))`; `ShortsViewModel` відкриває пейджер на цьому id (якщо його немає у стрічці — вставляє його першим).
- Нескінченність: коли до кінця списку лишається ≤5 елементів — `loadMore()`. Внизу: індикатор або рядок помилки з «Повторити».
- `PullToRefreshBox` лишається; під час refresh показується індикатор, список не очищується до приходу нових даних.
- Офлайн: `OfflineBanner` згори, якщо дані з кешу.

### 4.2 «Пошук»

- `LazyVerticalGrid(GridCells.Fixed(2))` → `LazyColumn` з `VideoCard` (один стовпець, повна ширина).
- Поле пошуку, дебаунс, кеш, `OfflineBanner`, `PullToRefresh` — без змін.
- `VideoGridCard` стає невикористаним → файл і тест видаляються.

### 4.3 Навігація

- `Routes.SHORTS_PATTERN = "shorts?videoId={videoId}"`, хелпер `Routes.shorts(videoId: String?)`; `videoId` — необовʼязковий аргумент (`nullable = true`).
- `ShortsViewModel` читає `videoId` із `SavedStateHandle`; якщо переданого id немає у завантаженій стрічці — вставляє його першою сторінкою пейджера, решту довантажує як зараз.
- `IOITubeApp`: видимість нижньої смуги визначається за префіксом `currentRoute?.startsWith("shorts")`, інакше з аргументом смуга зникала б. Вкладка Shorts без аргументу поводиться як зараз.

## 6. Ризики й обмеження

- **Вартість шортсів.** Один блок = 2 шортси = до 3–4 запитів таба каналу; сторінка з 20 відео дає 5 блоків → до 12 паралельних запитів. Помʼякшення: один запит на сторінку, паралельність обмежена, помилка блоку не блокує стрічку (блок просто не додається).
- **Порожні сторінки.** Деякі запити можуть повернути лише вже показані відео — максимум 3 спроби, далі `exhausted`, щоб не крутити вічне колесо.
- **Кеш.** Для теми/сортування кеш не використовується, тобто без мережі доступна лише стрічка «Усі + Релевантність».
- **Сортування «Нові»** залежить від `uploadedAt`; якщо YouTube не віддав дату — такі відео йдуть у кінець.

## 7. Критерії приймання

1. На «Головній» є чипи тем і сортування; вибір теми змінює вміст стрічки, а не лише фільтрує вже завантажене.
2. Два послідовні оновлення (pull-to-refresh) дають різні набори відео за тих самих теми й сортування.
3. Прокрутка вниз довантажує нові відео; блок Shorts зʼявляється після кожного 4-го відео і містить 2 шортси з різних каналів.
4. Тап по шортсу відкриває вкладку Shorts саме на цьому відео.
5. У «Пошуку» результати — один стовпець великих карток.
6. Помилка довантаження не очищає вже показану стрічку.
