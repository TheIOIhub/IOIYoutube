# IOITube — чекліст ручного тестування на пристрої

Документ для прогону застосунку на реальному телефоні. Автоматизовано верифіковано:
**166 unit-тести (0 failures, 2 skip)**, `assembleDebug` / `assembleRelease` (minified) / `assembleDebugAndroidTest` — усе зелене.
Живий прогiн проти YouTube (`IOITUBE_LIVE_TESTS=1`): стрiчка 30 вiдео, пошук, потiк + HLS-манифест з 17 варiантами якостi, опис, 20 коментарiв, стрiчка 125 шортсiв — ок.
Фаза 6: меню без підписів, згорнуті коментарі, вибір якості, поворот/повний екран, вкладка Shorts — сценарії 14–22.

## 1. Встановлення

Вимоги: Android **8.0+** (minSdk 26). Потрібен інтернет. Орієнтація: Головна/Пошук/Shorts — портрет, екран вiдео обертається вiльно.

Готові APK (теку `dist/` не комітимо, `*.apk` у `.gitignore`):

| Файл | applicationId | Призначення |
|---|---|---|
| `dist/IOITube-1.0-release.apk` | `com.ioi.youtube` | **Основний для тесту.** Підписаний, стиснутий R8 — саме він виявить проблеми мініфікації/рефлексії |
| `dist/IOITube-1.0-debug.apk` | `com.ioi.youtube.debug` | Резервний: якщо release падає — перевір той самий сценарій тут. Обидва ставляться паралельно |

```bash
# через adb (телефон у режимі налагодження, USB)
adb install -r dist/IOITube-1.0-release.apk

# або просто перекинь APK на телефон (Telegram/Google Drive/кабель) і відкрий у файловому менеджері
```

Якщо Android блокує встановлення — дозволь «Встановлення з невідомих джерел» для файлового менеджера.

## 2. Основний чекліст (спека §8)

| # | Сценарій | Очікувано |
|---|---|---|
| 1 | Відкрити застосунок | Стрічка ~30 звичайнiх вiдео (не прямi ефiри) змiшаних категорiй: прев'ю, назва, канал, перегляди, тривалість. Перше завантаження ~1–3 с, далi з кешу |
| 2 | Прокрутити стрічку | Плавна прокрутка, прев'ю довантажуються (Coil) |
| 3 | Тапнути відео | Плеєр стартує; опис без HTML-сміття (`<a href…>`, `&apos;`) |
| 4 | Прокрутити вниз на плеєрі | Секції «Коментарі» та «Рекомендації»; текст коментарiв без HTML |
| 5 | Тапнути рекомендацію | Відкрилося інше відео, «Назад» повертає на попереднє |
| 6 | Пошук «kotlin» | Сітка результатів через ~0.3 с (debounce) |
| 7 | Пустий пошук (пробіли) | «Нічого не знайдено», без креша |
| 8 | Авіарежим → головна | Банер «Немає з'єднання — показано кеш» + кешовані відео |
| 9 | Авіарежим → нове відео | «Не вдалося…» + кнопка «Спробувати знову» відновлює завантаження |
| 10 | Згорнути/розгорнути застосунок на плеєрі | Пауза при згортанні, продовження при поверненні |
| 11 | Поворот екрана | Поза плеєром нічого не змінюється (портрет); на плеєрі — сценарії 15–16 |
| 12 | Потягнути стрічку вниз (pull-to-refresh) | Індикатор оновлення, стрічка перезавантажується |
| 13 | Нижній бар | Три вкладки-іконки (Головна / Shorts / Пошук) без підписів, перемикання зберігає стан |
| 14 | Відкрити відео → блок коментарів | «Коментарі (N)» + «Показати коментарі»; списку немає. Тап → список, «Згорнути» → знову зникає |
| 15 | Повернути телефон на плеєрі | Відео обертається разом із телефоном і **не** перезапускається з початку |
| 16 | Кнопка «На весь екран» | Ландшафт, системні бари зникають, лишається тільки відео; «Вийти з повного екрана» → назад у портрет |
| 17 | Меню якості у плеєрі | Кнопка «Авто» у правому верхньому куті; у меню реальні якості з бітрейтом (наприклад «1080p · 4.3 Мбіт/с») |
| 18 | Обрати «1080p» | Картинка різкіша після кількох секунд буферизації, відео не перезапускається |
| 19 | Обрати «Авто» назад | Якість повертається до адаптивної |
| 20 | Вкладка Shorts | Вертикальна стрічка справжніх шортсів (9:16), автоплей, цикл, тап — пауза/відтворення |
| 21 | Свайп угору у Shorts | Наступний шортс грає автоматично, попередній зупиняється |
| 22 | Авіарежим → вкладка Shorts | «Не вдалося завантажити шортси» + «Спробувати знову» (кешу шортсів немає — очікувано) |

## 3. Пріоритетні зони ризику (не покриті автоматичними тестами)

Тестуй їх **у першу чергу** — це місця, де зламаність не була б виявлена локально:

1. **Release-збірка + NewPipe Extractor (R8).** Найвищий ризик: мініфікація могла зрізати рефлексивні шляхи NewPipe/OkHttp. Якщо release не завантажує стрічку/потік, а debug працює — це воно. Додай у звіт `adb logcat`.
2. **Час завантаження стрiчки.** «Головна» робить 5 паралельних пошукiв за категорiями — на повiльному мобiльному iнтернетi перший показ може зайняти кiлька секунд (далi — кеш). Якщо довго — повiдом.
3. **Відтворення відео (ExoPlayer):** старт, пауза/плей, seek, перехід між відео, вихід із плеєра (звільнення ресурсу), згортання/розгортання.
4. **Завантаження прев'ю (Coil)** — включно з битими URL.
5. **Поворот екрана** під час відтворення.
6. **Клік по рекомендації** та поведінка кнопки «Назад» (back-stack).
7. **Офлайн:** чи справді показується кеш і банер; чи не кешуються коментарі (очікувано — ні).
8. **HLS і меню якості.** Якщо якості не перемикаються або меню зникло — у `adb logcat -s IOITube` буде `HLS playback failed, falling back to progressive`: відео грає 360p, це передбачений вiдкат. Повідом iз логом.

## 4. Якщо щось впало — що прикріпити

Застосунок тепер логує справжню помилку мережi пiд тегом `IOITube`:

```bash
adb logcat -c                                   # очистити буфер
# ...відтворити проблему...
adb logcat -d -s IOITube                        # ← справжнiй стектрейс помилки
adb logcat -d -v time > logcat.txt              # повний лог
grep -E "FATAL|AndroidRuntime|IOITube" logcat.txt
```

Швидка перевiрка самої апки без телефону (потрiбна мережа):

```bash
IOITUBE_LIVE_TESTS=1 ./gradlew :app:testDebugUnitTest --tests "*SmokeTest*"
# очiкувано: live ok: feed=30 (… ms), search=…, stream=…, comments=…
# + рядок live shorts: n=… (… ms), hls variants=…
# + рядок live feed sample: …
```

Плюс: модель телефона, версія Android, який APK (release чи debug), і номер сценарію з таблиці.

## 5. Підпис release-APK (лише для тестування)

`release` підписано тимчасовим ключем (не для публікації):

- файл: `ioitube.jks` у корені репозиторію (у `.gitignore`)
- `keystore.properties` (у `.gitignore`): alias `ioitube`, store/key password `ioitube-test-2026`

Для публікації в Google Play потрібен **власний** ключ, збережений назовсім: згенеруй новий `keytool -genkeypair` і збережи паролі (втрата ключа = неможливість оновлювати застосунок).

## 6. Що не перевіряється автоматично назавжди

Експірація відеопотоків YouTube, зміни розмітки YouTube (NewPipe Extractor може ламатися від змін на боці YouTube), якість зображень/мережі. Якщо раптом зникає звук або частина відео — спробуй інше відео: це може бути формат потоку, а не застосунок.

Окремо: стрiчку «Головна» зiбрано з пошукових запитiв за категорiями (`NewPipeRemoteDataSource.FEED_CATEGORIES`), бо кiоск `Trending` у NewPipeExtractor 0.26.5 зламаний на боцi YouTube (HTTP 400 на `FEtrending`), а анонiмна домашня стрiчка YouTube порожня. Якщо YouTube поверне Trending — можна повернутись на кiоск одним рядком.
